# 会員データ簡素化 設計書

**版**: 1.0  
**日付**: 2026-06-03  
**前提**: 事業年度（2/1〜翌1/31）は変更しない。CSS（口座振替）は継続。会員承認フロー・強制退会（`expelled`）は**廃止**。3年滞納は**会費状況CSV**で確認し、**手動退会**（`status=expired`）のみ。

---

## 1. 目的

| 課題 | 方針 |
|------|------|
| 決済経路が `is_css_user` / `import_payment_kind` / `memberships.payment_method` で分散 | **カード / それ以外** の2値＋メモ（CSS はメモで明示） |
| 会員資格と会費年度の二重管理が分かりにくい | **日常UIは資格末日のみ**。事業年度は会費・未納判定用に DB 維持 |
| 3年未納の自動退会 Cron の誤爆・例外対応 | **自動退会廃止**。会費状況CSVの「3年連続未納」列で確認し、手動退会 |
| 承認待ち（pending）の運用負荷 | **承認フロー廃止**。入会・取込は `active` |
| 過去入金履歴 | `payments` は維持（監査・3年未納判定） |

---

## 2. スコープ

### 2.1 本設計に含む

- `profiles` への新カラム追加と既存データのバックフィル
- `is_css_user` の**非推奨化**（当面は残し、読み取りは新カラム優先）
- 会員資格表示用 `membership_valid_until` の denormalize
- 3年未納 Cron の**停止**（Vercel Cron 削除）
- 管理画面・API の変更方針（実装フェーズ一覧）

### 2.2 本設計に含まない（将来検討）

- `memberships` テーブル廃止（履歴として残す）
- 事業年度と会員年度のカレンダー統一
- Stripe Subscription への全面移行

## 3. データモデル（変更後）

### 3.1 profiles（追加・意味）

| カラム | 型 | 説明 |
|--------|-----|------|
| `payment_channel` | `text` | `'card'` \| `'other'`。会費の**継続徴収経路**の区分 |
| `payment_channel_note` | `text` | `other` のときの補足。**CSS は `'CSS'` 固定**（表示・CSV・絞り込み） |
| `membership_valid_until` | `date` | 会員資格の末日（4月基準会員年度の 3/31 等）。一覧・マイページ・コンクール照合の**主参照** |
| `expulsion_note` | `text` | 手動強制退会時の事務局メモ（任意） |

**既存（維持）**

| カラム | 役割 |
|--------|------|
| `status` | DB上は `active` / `expired`（`pending`・`expelled` はレガシー。表示は会員区分で吸収） |
| `stripe_customer_id` | `payment_channel = 'card'` のときのみ使用 |
| `expelled_at`, `expulsion_reason` | **レガシー**（新規の強制退会は行わない） |
| `is_css_user` | **非推奨**。マイグレーション 023 以降は書き込みしない。読み取り互換のみ |

### 3.2 payments（変更なし）

- `purpose = 'membership_fee'`
- `membership_fiscal_year` … **事業年度の未納・3年判定に必須**
- `method` … `stripe` / `transfer` 等（入金手段の監査用）

### 3.3 memberships（変更なし・裏方）

- 入会 Webhook / 年会費更新時に引き続き INSERT/UPDATE
- `membership_valid_until` は**最新 `memberships.expiry_date` と同期**（トリガまたはアプリ側）

## 4. 決済経路ルール

### 4.1 定義

```
card  … クレジットカード（Stripe Checkout / 1月自動引き落とし対象）
other … カード以外（CSS 口座振替、事務局手動入金登録など）
```

### 4.2 CSS の表現

| payment_channel | payment_channel_note | 表示名 |
|-----------------|----------------------|--------|
| `other` | `CSS` | 口座振替（CSS） |
| `other` | `NULL` またはその他文字列 | その他（メモ参照） |
| `card` | `NULL` | クレジットカード |

### 4.3 業務ルール

| 操作 | ルール |
|------|--------|
| Web入会（Stripe）完了 | `payment_channel = 'card'`, `note = NULL`, `stripe_customer_id` 設定 |
| CSS 会員（インポート・編集） | `payment_channel = 'other'`, `note = 'CSS'` |
| マイページ「カードに切り替え」 | `payment_channel = 'card'`, `note = NULL`, `is_css_user = false`（互換） |
| 1月自動請求 Cron | `status = active` かつ `payment_channel = 'card'` かつ `stripe_customer_id` あり |

### 4.4 `import_payment_kind` との関係

Excel 取り込み用の `import_payment_kind` は**当面維持**。023 バックフィル後は次の対応表で `payment_channel` を優先し、インポート処理改修時に両方更新する。

| import_payment_kind | payment_channel | payment_channel_note |
|---------------------|-----------------|----------------------|
| `css` | `other` | `CSS` |
| `web_transfer` | `other` | `CSS`（実運用が CSS と同一なら。異なるなら `口座振替WEB` 等） |
| `legacy_credit` | `card` | NULL |
| `other` | `other` | NULL またはメモ |
| `blank` | 既存 `is_css_user` から推定 |

## 5. 会員資格の判定（簡素化）

### 5.1 日常で使う条件（コンクール会員価格・マイページ）

```ts
function isMembershipCurrentlyValid(profile: {
  status: string;
  membership_valid_until: string | null;
}): boolean {
  if (profile.status !== "active") return false;
  if (!profile.membership_valid_until) return false;
  const today = ymdInJst(new Date()); // 既存ユーティリティに合わせる
  return today <= profile.membership_valid_until;
}
```

**事業年度はこの判定に使わない。**

### 5.2 事業年度が必要な場面（裏方・詳細タブのみ）

- 入会 Checkout 金額（11〜1月は翌年度会費）
- マイページ「未納の年度」と Checkout URL
- 1月22日 Cron の徴収対象年度
- **3年連続未納の退会候補判定**（`membership-three-year-arrears.ts` の既存ロジック）

### 5.3 `membership_valid_until` の更新タイミング

| イベント | 更新 |
|----------|------|
| 入会 Webhook 完了 | `maxPaid` 事業年度から算出した 3/31 を設定 |
| 年会費 Checkout / 1月 Cron 成功 | 同上（payments 再計算） |
| 管理画面で会員期限手動修正 | `memberships.expiry_date` と**同時に** `profiles.membership_valid_until` |
| バッチ（任意） | 最新 `memberships` から再同期 SQL |

## 6. 会員区分（表示）・3年未納・退会

### 6.1 管理画面の会員区分（DB `status` とは別）

| 区分 | 意味 |
|------|------|
| **会員** | `active`（またはレガシー `pending`）かつ資格期限内かつ直近3事業年度に未納なし・会費入金記録あり |
| **未納あり** | 有効資格があるが、直近3年度のいずれかが未納、または会費入金記録なし |
| **非会員** | `expired` / レガシー `expelled`、または資格期限切れ |

算出: `src/lib/member-display-status.ts`

### 6.2 自動 Cron 廃止

- `vercel.json` から `membership-three-year-expulsion` 削除済み
- API は `410`（誤実行防止）
- `shouldExpelActiveMemberForThreeConsecutiveUnpaidFiscalYears` は **会費状況CSV** の「3年連続未納」列用に維持

### 6.3 3年連続未納の確認

- **会費状況CSV（全会員）** に列: `会員区分` / `直近3年度に未納あり` / `3年連続未納`
- Excel で滞納・退会判断。一覧の「退会候補」「未納者」フィルタは**なし**

### 6.4 手動退会フロー

1. 会費状況CSVで `3年連続未納` = はい を確認（CSS は `payments` 登録漏れに注意）
2. 会員詳細の **「退会（資格喪失）」** または編集画面の退会ボタン
3. `DELETE /api/admin/members/[id]` → `status = expired`（データは削除しない）

**強制退会（`expelled`）・承認待ちフローは廃止。**

### 6.5 定期運用（推奨）

- **毎年2月上旬**: 会費状況CSVを出力し、3年連続未納と CSS 入金を突合
- 必要な会員のみ手動退会

## 8. CSS 会員の会費記録（運用必須）

自動退会を手動にしても、**未納判定は `payments` ベース**のまま。

| 運用 | 内容 |
|------|------|
| CSS で入金確認後 | 管理画面から `payments` に `membership_fee` を登録（`membership_fiscal_year` 必須、`method = 'transfer'` 等） |
| 登録しない場合 | 会員区分が「未納あり」、CSVで3年連続未納に誤って載る可能性 |
| 一覧表示 | `payment_channel_note = 'CSS'` でフィルタし、年度表と突合 |

（将来）管理画面に「○○年度会費を手動で支払い済みにする」ボタンを足すと運用負荷が下がる。

## 9. マイグレーション後の確認 SQL

```sql
-- 経路の内訳
SELECT payment_channel, payment_channel_note, COUNT(*)
FROM profiles
GROUP BY 1, 2
ORDER BY 1, 2;

-- is_css_user との不一致（ゼロ件が理想）
SELECT id, member_number, is_css_user, payment_channel, payment_channel_note
FROM profiles
WHERE (is_css_user = true AND (payment_channel <> 'other' OR payment_channel_note IS DISTINCT FROM 'CSS'))
   OR (is_css_user = false AND payment_channel <> 'card');

-- membership_valid_until 未設定の active 会員
SELECT id, member_number, status, membership_valid_until
FROM profiles
WHERE status = 'active' AND membership_valid_until IS NULL;
```

## 10. リスクと対策

| リスク | 対策 |
|--------|------|
| CSS 会員が未納・3年未納に誤表示 | 入金後は `payments` 手動登録。会費状況CSVで突合 |
| `membership_valid_until` のズレ | Webhook 更新時に必ず同期。月次で memberships との差分 SQL |
| 旧コードが `is_css_user` のみ参照 | Phase 2 で `payment-channel.ts` 経由に統一 |
| 手動退会の取り消し | 別途「復活」フロー（既存 `revive` API）を利用 |
